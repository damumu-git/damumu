# UI 预览到正式项目的同步

2026-10-27：将 `preview/` 中的默认浅蓝视觉应用到真实 Flutter / React 页面。
生产页面继续从现有 API 读取数据和提交操作，不导入 HTML 预览的模拟数据、状态选择器、
主题调节器、虚构统计或浏览器存储。

| 用途 | 值 |

| 页面背景 | `#F3F8FC` |
| 柔和背景 | `#E7F3FC` |

浅蓝底使用深色文字；保留红色危险操作及琥珀色待处理状态，不将所有业务状态改成蓝色。
App 继续使用仓库内的中韩字体，新增首页文案提供中英韩资源。

## 对应实现

| 范围 | 正式实现 |
| --- | --- |
| App 全局主题、输入、按钮、卡片、子页面、对话框及底部面板 | `app/lib/app_theme.dart`，由 `DaziApp` 应用 |
| 登录、注册及头像选择 | `app/lib/auth.dart` 使用同一调色板和全局控件主题 |
| 首页 | 深蓝介绍卡、独立搜索框、筛选标签及列表标题；保留实际定位、筛选、目录与分页 |
| 首页 / 发现的活动列表 | `EventCard` 使用上方封面、下方内容的竖版卡片，保留状态、参加人数、预计费用及风险信息 |
| 活动卡片的头像与新手友好 | 使用真实组织者头像、昵称、信誉；组织者声明与参与者认证分别标注 |
| App 五个主入口 | `_FloatingDock` 改为白色底栏、五项图标文字、浅蓝发布按钮；保留未读和草稿离开保护 |
| 发布、活动详情、我的活动、资料、设置、安全及反馈 | 原有业务页面应用共同主题；表单字段、权限和操作不替换为演示流程 |
| 消息 / 聊天 | 可换行的分类标签、浅蓝本人气泡；保留实时同步、重试、撤回、举报及图片鉴权 |
| Admin 十个栏目、详情及编辑弹窗 | `admin/src/preview-theme.css` 在原布局样式之后加载，使用白色侧栏、浅蓝主操作、18px 卡片及可读字号 |
| Admin API 与业务流程 | `App.jsx` 只增加主题样式导入；原资源加载、筛选、审核、治理、公告和编辑请求保持原实现 |

正式活动使用 API 提供的封面；没有封面时显示分类图标，不把预览插画当作真实活动照片。
正式数据长度、用户语言与设备字体会影响排版，HTML 预览仍是设计参考，不是平台间像素一致的保证。

## 后续调整

- 预览默认主题在 `preview/shared/`；正式 App / Admin 的值分别在上述主题文件。
  修改预览不会自动覆盖生产代码，后续设计调整应同时维护这些文件。
- 真实组件的回归验证使用 `flutter test`、Admin lint/build；需要生成 Flutter 实际渲染图时运行：

  ```powershell
  cd app
  flutter test --dart-define=WRITE_UI_CAPTURE=true test/preview_sync_test.dart
  ```

  图片输出到 Git 忽略的 `.dev-data/ui-captures/`，不会打包进发布版本。
- 无需 API 或数据库迁移。Admin 按原流程构建部署，App 按平台重新构建发布。
  本次修改没有在 AWS 部署，也没有生成 Android / iOS 商店包。
