# DAMUMU 项目说明

## 产品定位

DAMUMU（中文 UI 名称“搭慕”）是一款面向韩国本地生活场景的线下活动发现、发布与结伴应用。核心流程是用户注册或登录后发现活动、查看详情、报名或申请、由组织者处理申请，并在获得批准后参与活动和交流。

## 核心模块

- 用户认证、个人资料与头像。
- 活动分类、行政区域、活动发现与筛选。
- 活动发布、报名、候补、组织者审批与参与记录。
- 站内通知、活动群聊、私信及安全治理（部分安全治理仍待接入真实数据）。
- 用户端 App、运营管理后台和独立产品介绍网站。

## 系统组成

- `app/`：Flutter 用户端，覆盖 Web、Android 和 iOS。
- `restapi/`：ASP.NET Core REST API。
- `restapi/Migrations/`：按编号执行的 PostgreSQL 迁移。
- `admin/`：React/Vite 运营管理后台。
- `website/`：独立静态产品介绍网站。
- `preview/`：App / Admin 两个离线 UI 设计预览入口，示例数据与正式服务隔离；用于视觉评审，不自动发布或同步生产页面。
- `docs/`：项目上下文、当前状态与架构决策。

## 技术栈

- Backend：ASP.NET Core 10 Minimal API、Npgsql 10。
- Database：PostgreSQL、PostGIS；当前远端业务数据库名为 `damumu`。
- App：Flutter、Dart、Material 3。
- Admin：React 19、Vite 8。
- Infrastructure：AWS Lightsail 单机测试环境；本地 App 开发默认使用公网 HTTPS API，本地 REST API 开发需使用隔离数据库或 SSH 隧道。
- Media Storage：Lightsail 单机使用宿主机 `/srv/damumu/uploads`，仅挂载到 API；磁盘路径与公开媒体 URL 分开配置，API 返回完整 HTTP(S) 图片 URL。对象存储尚未接入。
- Realtime：ASP.NET Core 原生 WebSocket；数据库和 REST API 仍是消息事实来源，WebSocket 只发送同步事件，多 API 实例通过 PostgreSQL `LISTEN/NOTIFY` 转发轻量事件。
- Push：Firebase Cloud Messaging（FCM）已接入，但在完整外部处理披露核定前由客户端发布开关和服务端 `Privacy:ExternalPushApproved` 默认停用，不影响站内消息和前台 WebSocket。

## 长期业务规则

- 平台不收取活动费用，不提供支付、转账、托管、退款或资金担保；金额仅表示组织者填写的线下预计人均韩元支出。
- 精确集合地点只允许组织者以及状态为 `approved` 或 `attended` 的参与者读取。
- 新活动当前直接发布，不强制经过管理员预审。
- 活动分类、行政区域和生产活动列表以 API/数据库为准，不在客户端重新维护硬编码目录。
- 发布页默认展示六个精选一级分类和“其它”；每个一级分类都有固定的“其它”二级分类，自定义名称限 15 字，按活动存储，不创建全局分类。
- 活动封面选填一张；用户可直接选择设备照片，客户端预缩图、按 4:3 裁剪并输出 1280×960 JPEG。1.5 MB 是处理后上传文件的上限，不是原照片的选择限制。
- 活动列表和聊天消息使用 640px/320px WebP 缩略图，用户打开图片预览时才加载原图；媒体 URL 使用不可变 UUID 文件名并长期缓存。当前不提供视频或 Live Photo 上传下载，月度出站流量达到 2 TB 时评估对象存储/CDN。
- 活动容量包含组织者本人；组织者是第一个已批准参与者。
- 发布者可以声明活动适合新手；组织者在已结束活动中累计获得至少 3 名不同参与者的“新人友好”正向评价后，其后续活动显示“参与者认证”的新手友好标记。声明与认证必须在界面上区分。
- 每个活动有唯一活动群聊；组织者以及状态为 `approved`、`attended` 的成员默认可以访问，成员状态变化会同步群聊成员资格，用户主动退出群聊后不会被自动重新加入。
- 最低注册年龄14岁，采用主动年龄自我确认及当前隐私政策阅读确认，不宣称已进行实名或成年验证。外部推送和地理编码在跨境告知核定前默认停用。
- 聊天消息自发送起、活动及其群聊自最终结束或取消起、举报及其证据自提交起保留3个自然月；到期清除内容及无其他有效引用的媒体。活动群结束7天后只读，取消时立即只读。聊天图片必须登录并具有会话权限，使用私密非持久缓存。
- 喜欢与举报只允许同一活动中状态为 `approved` 或 `attended` 的成员在活动结束后提交，每人对同一活动或同一成员各一条；活动反馈计入组织者，成员反馈计入目标用户。喜欢总数和高频正向标签可公开展示；举报不公开原始数量和举报人，只有同一标签得到至少 3 名不同参与者举报时才显示该标签，已驳回举报不参与提示。
- 用户确认注销后立即撤销认证与推送凭据并清除个人资料、个人头像、安全联系人等信息；必要内容在原有有限期限内以默认头像和注销数字占位，不宣称不可逆匿名化。注销3个月且必要关联解除后删除账号占位记录。删除前签发的访问令牌必须立即失效。
- API 使用统一的 `{ data, meta, error, traceId }` 响应封装，不向客户端泄露 SQL、堆栈、凭据或内部连接信息。
- 用户端服务器读取失败时使用统一内容区错误状态，不显示原始 HTTP、解析器或数据库异常。
- 未实现功能必须如实标注，不得把说明性占位页描述成已完成能力。

## 外部服务与依赖

- PostgreSQL/PostGIS：业务数据、地理位置与目录数据。
- 浏览器/设备定位：附近活动和本地化位置标签。
- Apple、Google、短信认证、对象存储和推送服务尚未作为生产依赖确定。
