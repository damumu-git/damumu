# DAMUMU 当前项目状态

最后核对：2026-09-30（Asia/Seoul）。本页只记当前事实、下一步和阻塞；完成历史见 Git。代码、迁移和测试结果优先于本页。

## 当前已接通

- 用户信息页支持点击头像进入全屏预览，支持缩放、关闭和图片失败兜底。“我的活动 → 我发布的 → 管理详情”支持填写必填取消原因（最多 500 字）并取消活动；详情和列表同步显示取消状态与原因，取消后隐藏取消与审批入口。API 在同一 SQL 事务中保存取消状态、活动群系统消息和有效群成员通知，重复取消不会重复发送；群内通知按“活动取消 / 取消原因”展示，并通过现有 WebSocket/FCM 链路提示同步。使用现有数据库字段，无新增迁移。

- 通知和聊天已接入真实 API：报名时通知组织者，组织者审核报名后通知申请人，Admin 审核活动后通知发布者，后台官方公告通知所有活跃用户，新聊天消息通知其他会话成员。活动创建时自动生成唯一活动群聊，组织者和获批/已签到成员自动加入，退出活动或状态失效后自动离开；用户也可单独退出群聊。消息页展示真实活动群、私信和通知，底部导航、分段和列表均有未读标记；支持右滑已读、左滑退出群聊或删除个人列表项、一键全部已读，通知点击后进入详情。登录后的 Flutter 通过首帧认证 WebSocket 实时接收消息和通知同步事件，断线指数退避重连；FCM 设备注册和服务端投递链路已实现，提供 Firebase 配置后启用后台系统通知。
- Windows 开发启动和 Tailscale PostgreSQL 测试脚本只从环境变量读取数据库密码，不再暂停等待手动输入；可使用 `DAMUMU_POSTGRES_PASSWORD`，启动脚本也支持完整的 `ConnectionStrings__Muda`。`dev.ps1` 会记录 API 和 Admin 的 PID，原窗口关闭后可用 `stop-dev.ps1` 安全停止其进程树。
- 开发数据库已应用 `013` 至 `016`：活动创建时生成唯一群聊并立即加入组织者，获批/已签到成员随状态同步，可登记 FCM 推送设备，并支持会话个人隐藏、主动退出群聊和通知软删除。已通过真实 API 生成 DEMO 批次 `20260921-141112`，包含 20 个注册会员、20 个活动、20 条通过申请、20 条拒绝申请、20 条待审核申请、20 个活动群、10 个私信会话和 60 条消息；登录清单保存在本机 Git 忽略的 `.dev-data/`。
- App 发布页的大分类使用横向 emoji＋文字矩形按钮，窄屏每行两个；默认展示六个精选分类和“其它”，新增大分类可展开。每个大分类下有“其它”小分类，选中后输入最多 15 字；顶级“其它”保留直接输入。开发数据库已应用 `012`，新增大分类由触发器补齐“其它”叶子。`icon_key` 保留，但 App 当前不加载分类插画。
- 发布活动可选一张封面；客户端选设备照片后先缩图，再固定 4:3 裁剪、自动压缩，输出 1280×960 JPEG，最终上传文件最多 2 MB。界面明确原图无需预先压到 2 MB，并显示处理后大小；裁剪后可预览、水平翻转、更换和移除。API 验证图片并存于本地 `uploads/events`，活动列表和详情返回封面 URL；上传后发布失败会尝试删除未关联文件。
- Web 裁剪器缺少 Cropper.js 资源造成的无裁切框、无法旋转和确认无响应已修复；1.6.2 的 JS、CSS 与许可证随 App 本地提供。浏览器隔离组件实测裁切框显示、左旋和确认返回图片；头像上传还补齐了 multipart JPEG 类型，并在上传前新增预览及水平翻转。

- App 五个一级页面保留底部菜单；活动详情、聊天、活动记录、设置和安全中心等子页面顶部提供“回首页”，可从深层页面直接返回首页。发布表单有未保存内容时，切换一级页面、返回或回首页均提示确认。

- App 发布页支持“从过往活动中发布”，本人已发布活动列表及记录详情支持“发布同类活动”；通过带登录态的 UUID 详情请求预填名称、介绍、分类、地区、集合点、人数、预计费用和审核设置，开始/结束日期时间清空后必填。新增文案覆盖中英韩。

- Flutter 可通过 API 完成账号登录、资料与头像、分类和地区加载、单次活动发布、首页及发现活动列表，以及“我的活动”和组织者对待处理申请的批准／拒绝。
- 首页和发现使用 `/activities` Cursor 分页，按创建时间与 UUID 排序；搜索和筛选仅针对已经加载的活动。活动结束时间已过时，App 标注“过去活动”并停用详情报名按钮。
- 活动详情、加入、退出和组织者待审核列表已接入真实 API。待审核报名不计入参加人数；申请可填写备注，任何历史状态都禁止同一用户再次申请。组织者、已通过成员和申请人头像可进入只展示头像与名字的公开用户页，申请列表显示提交时间和备注。
- 当前数据库经 Tailscale 访问；开发启动和集成测试脚本使用外部提供的密码。2026-09-18 已对开发数据库按序应用 `010`、`011`、`012`；`012` 后有 7 个需要自定义名称的分类叶子。隔离端口 API 集成测试通过，运行中的旧 API 需重启以加载本次代码。

## 已知缺口与验证边界

- 2026-09-30 取消活动改动通过 API 构建和 PostgreSQL 临时表测试：原因校验、组织者权限、已完成/已删除状态、通知失败时原子回滚、重复取消去重、有效群成员通知。另有 9 项 Flutter 相关测试全部通过，覆盖头像预览关闭、原因必填、失败重试、取消后的列表刷新、普通成员无取消入口、群通知样式及原有页面回归；Flutter 静态分析通过。测试未修改业务数据；尚未进行真实账号多浏览器联调。

- 活动和地点创建尚未处于同一个数据库事务；失败时可能留下孤立地点。
- 搜索、分类和日期筛选仍仅覆盖已加载页面，尚不是服务端全量筛选。
- Flutter 的活动模型仍保留旧整数/hash ID 供现有页面键值使用，同时以 `apiId` 承载详情及参与 API 的 UUID。
- 用户令牌和管理员静态 API Key 仍属开发阶段方案；头像文件使用 API 本地目录。
- WebSocket 连接表当前在单个 API 实例内存中；多实例部署需要 Redis 等跨实例事件总线。Firebase 未配置前，FCM 自动停用，后台系统通知不可用，但站内通知和前台实时同步不受影响。统计和部分安全治理 UI 仍含演示数据或占位说明。
- 其他数据库环境仍须按顺序应用 `013_notifications_event_chat.sql`、`014_event_chat_organizer_membership.sql`、`015_push_devices.sql` 和 `016_member_profiles_and_message_actions.sql`；`014` 修复活动与组织者成员在同一 SQL 语句创建时，成员触发器看不到新群聊的问题。
- 原有注册 Golden 测试引用 macOS 专用字体路径，在 Windows 上不能通过；不要仅为通过测试更新快照。
- 加载失败状态在窄面板中改为紧凑重试按钮，避免文字按钮横向溢出。
- Flutter SDK 锁文件与分析缓存位于用户目录，受限环境运行检查时可能需要允许缓存写入。
- 其他数据库环境的 `010`、`011`、`012` 迁移状态未知；真实账号的“其它”、头像上传及带图发布尚未验证。浏览器或设备无法解码的极大 RAW/非标准照片会提示改选普通照片或导出 JPEG，不能保证直接处理 1–2 GB 文件。封面当前使用 API 本地目录，跨实例共享和持久对象存储尚未接入。
